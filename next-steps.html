How the scaffold enables parallel work

The key decoupling

Stage 1 adapter

src/stage1_adapter.py is the only file in Stage 2 that knows about Stage 1's storage format. When Yiheng iterates (K=4 → K=8, or swaps to fit_mlp_irt.py), only the adapter changes. Trainer, inference, tests stay untouched.

Submissions directory pattern

One subdir per variant. Independent. Nobody blocks anyone.

submissions/
├── smoke_test/             (floor)
├── v1_irt_k4/              Joey  · first real
├── v2_irt_k4_mlp/          Joey  · MLP head iteration
├── v3_irt_k8/              Joey  · after Yiheng's K=8
├── v4_llm_judge_zs/        C     · zero-shot judge
├── v4_llm_judge_fs/        C     · few-shot w/ labeled
└── final_ensemble/         joint · log-mixture
Manifest-driven config

manifest.json carries K, model type, run name, encoder. Stage 2 reads it and configures itself — no hardcoded constants. Avoids invisible coupling when K changes.

CI + submission discipline

tests/check_contract.py gates every PR via the existing GH Actions workflow. A schema-break PR shows red before review. Plus: no Codabench submit without an offline-validation gain — prevents the team from racing on the leaderboard and burning the 1000-total cap.
